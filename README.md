# SOKUNOBANK(即納バンク)※仮称

法人の発注担当者向け「急ぎ発注・最短納期比較サイト」。

**コアバリュー**:即納バンクに来れば、欲しいものが今日/明日届くか、どこに頼めば一番早いかが一目でわかる。

- 公開URL: https://sokunobank.com/
- 「今日中/明日までに◯◯が欲しい」という法人の発注担当者向けに、カテゴリーごとの最短納期・料金を比較する

> **注記:** 「SOKUNOBANK」は暫定名称。商標の最終確認(J-PlatPat)は未完了。

selected-by(ファッション・美容EC比較サイト)とは完全に別プロジェクト。リポジトリ・デプロイ先とも分離している。技術スタックの「作法」のみ参考にし、コンテンツ・コードは流用しない。

---

## 対象とする商材の原則(最重要)

このサイトの価値は**「発注プロセスが複雑で分かりにくい」商材にのみ発生する**。

- **対象**: DM発送代行、印刷、名刺、印鑑、胡蝶蘭などの専業サービス。締め切り時刻・データ準備・宛名リストなど複数の要素が絡み、発注者自身では「結局いつ届くのか」を判断しにくいもの
- **メインコンテンツにしない**: Amazon等の物販。商品ページを開けばAmazon自身が「お届け日」を即答するため、比較サイトを経由する理由がない

新しいカテゴリーを検討する際は、必ずこの原則(発注プロセスの複雑さ)に照らして対象かどうか判断すること。

## Amazonの扱い(「レジ横」方式)

> **現状(2026-09-23〜)**: アソシエイト審査完了(StoreID: `sokunobank-22`)。第1弾として
> [/guides/dm-self-shipping/](src/pages/guides/dm-self-shipping.astro)(少量のDMなら自分で発送する方法)を公開し、
> はがき・封筒・宛名シール・コピー機・インクジェット用紙(チラシ用)へのリンクを実装済み。
> **180日ルールの期限は2027-03-22**(このアソシエイトIDで3件以上の売上が必要)。

- 独立したカテゴリーページ・比較ページは作らない
- 各専業サービスの記事内で、文脈が自然な箇所にのみテキストリンクとして挿入する(例:DM記事内で「宛名シールも急ぎなら」)
- バナーや商品一覧のような、目立つ形での掲載はしない
- リンク形式:Amazon検索結果ページ+アソシエイトタグ
  `https://www.amazon.co.jp/s?k=検索キーワード&tag=アソシエイトID`
- PA-API(商品情報取得API)は申請・利用しない。在庫・価格・配達日はAmazon側の実ページに委ねる(配達日は分刻みで変動するため、自前で再現・計算しない)
- リスティング広告等で即納バンク自体への流入を増やすのは問題ない想定。ただし広告自体がAmazonへの直接リンクを含む場合は、2026年4月のAmazonアソシエイト規約改定により紹介料対象外になるため注意
- 180日ルール(登録後180日以内に3件以上の売上がないとアカウント閉鎖)への対応:独立カテゴリーを作らない方針を優先する。達成できなければ、トラフィックが育ってから再申請すればよいと判断済み

## ページ構成(3層)

1. **トップページ**:緊急度による絞り込み(今日中/明日まで/今週中)を最上部に配置。カテゴリー一覧はその下に配置
   - 現状の実装では「急ぎの目的から探す」セクション(`src/pages/index.astro`)がこれに相当するが、「今日中/明日まで/今週中」という明示的な3段階フィルタにはなっていない
2. **カテゴリー比較ページ**:業者比較+逆算シミュレーター(締め切りルールが固定的な業者向け、後述)
3. **業者別詳細/送客ページ**:発注時の準備物・注意点をまとめ、アフィリエイトリンクへ送客
   - **現状との差分**: 現在は層2と層3を分離しておらず、`/categories/<slug>/` 1ページ内に比較表と各社詳細(`ProviderCard`)をまとめて表示している。独立した業者別ページ(例:`/categories/dm/raksul/`)は未実装

## 逆算シミュレーター(コア機能)※未実装・設計方針のみ

「今日◯時までに申し込むと、いつ届くか」をブラウザ側(JavaScript)でその場で計算する機能。**現時点ではコードに実装されていない。**

- 保持するデータ:締め切り時刻、発送までの営業日数、祝日リスト、最低ロット数のみ
- 具体的な日付はデータとして持たない。訪問者がアクセスした瞬間の「今日の日付」から逆算するため、カレンダーの手動更新が発生しない
- カテゴリー非依存の設計とし、DM以外(印刷・梱包資材等)にも横展開可能にする(`src/data/schema.ts` の `CategoryData` に、後日 `cutoffRules` のようなオプションフィールドを追加する形を想定)
- **Amazon商材には適用しない**。配達日が分刻みで変動するため、自作すると不正確になるリスクが高い

## 技術アーキテクチャ

### プラットフォーム

- [Astro](https://astro.build/)(静的サイト生成、`output: "static"`)
- Cloudflare Workers(Static Assets 機能でホスティング。selected-byと同様の構成。`wrangler.jsonc` 参照。PHPは不使用・不要)
- TypeScript

### データ構造

ダイレクトメール(DM)は最初の1カテゴリーに過ぎない。今後、印刷・段ボール・名刺・印鑑・胡蝶蘭などを
追加していく前提で、カテゴリーをコードにハードコードせず、データ(JSON)として定義する設計にしている。

- **カテゴリー定義**: `src/data/categories/*.json`(スキーマは `src/data/schema.ts`)
  - 比較項目(発送スピード・最低依頼数・単価帯など)はカテゴリーごとに可変な `comparisonFields` として定義する
  - DM固有の項目名やテキストはコンポーネント側にハードコードしない
  - 新しいカテゴリーを追加する場合は、同じスキーマの JSON ファイルを1つ置くだけでよい(ルーティング・コンポーネントの変更は不要)
- **ルーティング**: `/categories/<slug>/`(比較ページ)、`/lp/<slug>/`(広告LP、`lp` データを持つカテゴリーのみ生成・`noindex`)
- **コンポーネント**: `src/components/*` はすべてカテゴリー非依存。テキスト・項目名はすべて props 経由でデータから受け取る

### 今回のスコープ

- 上記の設計を実装した上で、実際にデータを入れて公開するのは **DMカテゴリーのみ**
- `src/data/categories/printing.json` は将来カテゴリー追加用の空テンプレート(`status: "draft"` のためルート未生成)
- 逆算シミュレーター・Amazon「レジ横」リンク・業者別詳細ページの分離は、いずれも次フェーズ以降の実装課題(上記の各セクション参照)

## DMカテゴリーの内容について(重要)

- メイン推奨(送客軸)は **ラクスル(ラクスルDM便)**。ValueCommerceに広告主登録あり・提携確認済みという前提で設計しているが、実際のアフィリエイトリンクは未発行(`officialUrl` / `affiliateUrl` は空欄)。
- 地区宅便との提携でシステムを刷新し、見積もり〜注文完了までのリードタイムを最短1日に短縮(従来は約1か月)したという情報があるが、**この具体的な「最短1日」という数値は未検証**(`dm.json` の `lp.hookVerified: false` のまま)。公開前に公式情報で確認すること。
- 参考掲載の4社(セルマーケ / NEXLINK / ゼンリンマーケティングソリューションズ / DM発送代行センター(メディアボックス))には**アフィリエイトリンクを付けない**。比較・信頼性のための参考情報としてのみ掲載し、データ上も `officialUrl` は空欄・比較項目は「要確認」としている(数値の推測・古い情報での穴埋めはしていない)。A8.net/ValueCommerceへの広告主登録は未確認(Web調査では見当たらず。管理画面での最終確認はユーザー本人が実施予定)。
- コンテンツには「フルおまかせ型」と「データ持ち込み型」の2軸を設けている。翌日発送が実現できるかは業者の処理速度よりも、発注者側が宛名リスト・デザインデータをどれだけ事前に用意できているかに左右される、という視点を反映するため。
- ラクスルは**1通から発送可能・最短翌日発送**(2026-09-23確認、旧: 500通〜・最短当日発送という記載は誤りだったため修正済み)。企業リストは**購入のみ対応(レンタル不可)**。

## 運営者情報の秘匿

サイトを辿って運営者が特定の個人であると外部から判明しないよう、以下を徹底している/徹底すること。

- 運営者情報・お問い合わせ先には屋号「SOKUNOBANK運営事務局」を使用し、個人の本名・住所・電話番号は掲載しない(`src/pages/about.astro`, `src/components/Footer.astro`)
- お問い合わせ用メールアドレスは `dmsales29@gmail.com`(事業用、ValueCommerce登録にも使用)を設定済み
- HTMLメタデータ(`<meta name="author">` 等)に個人名・個人メールアドレスは含めていない
- 画像・PDF等を追加する場合は、EXIF等のメタデータに個人を特定できる情報(撮影者名・GPS位置情報等)が残らないよう、掲載前に確認すること
- Gitのコミット履歴は本プロジェクト専用のユーザー名・メールアドレスをローカル設定済み(`git config --local`、`user.name = "SOKUNOBANK運営事務局"`, `user.email = "dmsales29@gmail.com"`)。グローバル設定は変更していないため、他のリポジトリには影響しない
- ドメイン登録時は、レジストラのWHOIS情報公開代行(プライバシープロテクション)を必ず有効にすること(実際の登録作業はユーザー本人が行う)

### 前提として理解していること

- ValueCommerceへの登録自体(本人確認情報の提出)は法律上必須のため対象外
- ValueCommerce経由の通常の仕組みでは、広告主(ラクスル)に個々のアフィリエイターの個人情報が直接開示されることはない。上記の対応は、あくまで「サイトから辿って外部の第三者が個人を特定できる経路」を塞ぐためのもの

検索エンジンに加えて、ChatGPT等のAI回答エンジンに引用・選定されることも意識している。詳細な運用ルールは [CLAUDE.md](CLAUDE.md) 参照。
